# Spider-Man (2002, Xbox) → PC: port notes

Static recompilation with [xboxrecomp](https://github.com/sp00nznet/xboxrecomp),
cloned at `C:\Users\adub9\xboxrecomp`. Read this first in a new session.

## Layout

| Path | What |
|---|---|
| `C:\Users\adub9\xboxrecomp\game_files\` | unpacked disc: `default.xbe` + `data\` (not in git) |
| `regen.sh` | whole pipeline (disasm → func_id → abi → Ghidra names → lift to C) + build; `regen.sh lift` = lift + build only (after editing recomp_manual.c) |
| `run.ps1` | run the exe for N seconds with env switches; logs to `run_out.txt` / `run_err.txt` |
| `seeds\manual_seeds.json` | function entries found by hand, fed to the disassembler |
| `src\recomp\gen\` | generated C (regenerated by `regen.sh`; don't edit) |
| `src\main.c`, `src\recomp_manual.c` | hand-written host code and overrides |

Ghidra 12.2 is at `C:\tools\ghidra`. From inside the Claude app it must run with
`JAVA_TOOL_OPTIONS=-Dapplication.settingsdir=C:\tools\ghidra\settings` (the app
redirects AppData), and needs its bundled Jython extension (installed).

## Toolkit changes (branches in xboxrecomp)

- `fix/reserve-stdio-names` (committed): `<stdio.h>` names are mangled in generated
  identifiers. Spider-Man's CRT `flushall` clashed with UCRT (C2371).
- `feat/nv2a-sw-method-irq` (on top of the above, committed 27df937):

## Walls so far

1. **Build: `flushall` C2371.** Fixed (stdio reserved names).
2. **Controller init ICALL to 0x00379DAC unresolved.** XPP one-time init the
   disassembler never found. Seeded in `seeds\manual_seeds.json`.
3. **Hang in D3D init, before the first frame.** D3D's fence wait
   (0x002F2B00) patches a "wake me" NOP (value 5) and sleeps on device+0x2440;
   no GPU interrupt woke it. ISR 0x002FB6C0 → DPC 0x002FBF10 → PGRAPH handler
   0x002FBCA0 → software-method routine 0x002FBA00. RECOMP_NV2A_SWMETHOD
   delivers the interrupt (values 8 and 9 are handled), but the real stall was
   the fence wait spinning on the GPU semaphore: device+0x34 points at it
   (0x80003000; XDK 4134, later XDKs use +0x30) and the executor never wrote
   it. Fix: `sub_002F2B00_enter` in recomp_manual.c hands it to
   `nv2a_pb_set_semaphore_target`.
4. **First screen drawn (2026-10-24):** the legal/logos screen renders
   correctly (frames\f_00009.bmp). ~3,000 draws, fence count 11 → 81.
5. **Wait failing after the legal screen:** KeWaitForSingleObject returned
   0xC0000001 in a loop: D3D waits on a KEVENT it built by hand. Fix:
   `RECOMP_TITLE_KEVENTS=1`. After it, both intro movies play (ACTIVISN.bik,
   TREYARCH.bik; Bink draws through the overlay, so frame dumps are black).
   NB: run.ps1's watchdog used to end every run at 16 s - it's a timer, not a
   hang detector. Now it fires 3 s before -Seconds.
6. **Crash loading the start screen** (bonus\START.xbs, menu sounds), reading
   0xB4000000 after wild ICALLs (0x822400B4, 0). Two missed function entries,
   both seeded:
   - 0x002BEDCD, a CRT callback dispatcher called thousands of times. The
     function before it ends in a call to 0x2A98D4 (thread exit, never
     returns) and the disassembler ran on into it. **Pattern to watch**: if more
     functions hide behind no-return calls, teach tools.disasm which calls don't
     return instead of seeding each one.
   - 0x0030C072, a lone `ret` (MSVC folds empty functions onto one).
   The crash itself was a **toolkit bug**: sub_0003B690's two switches use
   MSVC's two-level form (`movzx edx, byte [edx+BYTES]; jmp [edx*4+ARMS]`) with
   a one-entry dword table, and the lifter refused one-arm tables, so each
   became an unresolvable tail jump (ICALL 0x0003B73E) and the function
   returned early. Fix on branch `fix/byte-indexed-one-arm-switch` (lifter
   accepts a one-arm table indexed by a byte table; tests in
   test_lifter_local_jump_table.py). Full suite: 889 passed, 21 skipped (they
   need clang/gcc, not installed), tools/fusion ignored (needs `pefile`).
7. **Title screen reached (2026-10-24).** Boot order works end to end: legal
   screen → Activision and Treyarch movies → ORIGIN1 intro (46 s) → START.xbs
   title screen "Press START" → attract mode replays ORIGIN1. No failed calls.
   Movies do show in frame dumps. A run needs ~150 s to reach the title.
8. **Controller never seen** (2026-10-24). Three layers:
   - `RECOMP_USB=1` is needed, and **main.c must call `xbox_OhciInit()`** -
     the template never did, so the USB model never started (added after
     the memory layout init; also a template bug worth sending upstream).
   - The pad then enumerated and XInputGetState succeeded with the packet
     number ticking, but buttons stayed 0. **Toolkit bug**: ohci.c's
     bus_resolve sent any address below the contiguous high-water mark to
     the window; Spider-Man allocates ~41 MB of contiguous memory within a
     second, so XPP's heap report buffer (~0x0118xxxx) was resolved to the
     window. Fix on branch `fix/ohci-ram-named-buffers`: honour
     xbox_PhysRamNameMap, as the APU already does.
   - Game side: sub_000152D0 = per-frame device changes (XGetDeviceChanges
     0x37ADA7, XInputOpen 0x37A9E9, XInputGetCapabilities 0x37AA6A, XInputClose
     0x37AA5E); sub_00015430 = poll one port (XInputGetState 0x37AC5C into
     port object +0x08, buttons at +0x0C). Port objects: table at [0x3F5A00]+4.
9. **IN GAME (2026-10-24).** Tapping Start every 3 s: skips movies → title →
   main menu (MENU.xbs) → loading screen → **ORIGIN_Z training level with
   Peter Parker (PETERSTU.xbs), HUD and health bar** → pause menu. No crash in
   108 s. Frames: frames\menu\m_00920 (cutscene), m_00955 (gameplay).
   **Next:** real input (keyboard/pad) to move around; check speed (fps).

Frame dumps: add `RECOMP_FB_DUMP="frames\f_"; RECOMP_FB_DUMP_FLIPS="1"` to the

## Performance (2026-10-24)

Training level: 5-8 fps. Menus/movies 20-26. Measured per thread over 5 s in
the level: ~7.5 cores busy - 11 raster workers at ~53% each, the NV2A poll
thread (walk + raster) ~80%, the game thread ~70% (largely waiting on the
GPU fence). 640x480, no AA; ~780k triangles rasterised per report window.
**CPU rasterising is the bottleneck.** Fix: a D3D11 render back end through
nv2a_backend.h (clear/draw/flip; gets clipped triangles, stage-0 texture,
blend/depth/stencil). Not passed to back ends yet: register combiners and
texture stages 1-3, so effects using them would need the interface extended.
`RECOMP_D3D_PRESENT=1` (in play.bat) only moves presentation to the GPU.

## GPU renderer (src/gpu_backend.c, RECOMP_GPU_RENDER=1, on in play.bat)

D3D11 back end through nv2a_backend.h: picks the adapter with the most VRAM
(the RTX 4070), one BGRA8 render target per colour surface and a D32S8 depth
buffer per zeta, render-to-texture sampled directly, textures decoded by the
toolkit and cached with a sparse checksum, GPU mips, blend/depth/stencil/
alpha-test/colour-mask/depth-clip. Dirty targets are read back into guest
memory at flip, so the window, presenter and frame dumps work unchanged (one
frame of latency). Not yet: register combiners, texture stages 1-3,
CLEAR_RECT, culling.

Result in the training level: 12-13 fps (was 5-8), ~1.7 cores busy. The
jacket speckles are gone (a CPU-rasteriser bug). **New bottleneck: the NV2A
poll thread at ~85%**, running vertex programs on the CPU (nv2a_vsh_interp)
for ~12k triangles a frame; the game thread (~68%) mostly waits on it.
Options: spread vertex processing over worker threads (the raster pool is
idle now), or run vertex programs on the GPU (needs the back-end interface
to pass raw attributes, program and constants; xbox_d3d8 already has an
NV2A microcode -> HLSL translator).

### Speed-up round (2026-10-24): 12 -> 53-60 fps in the training level

- gpu_backend.c: pick_adapter() ran on every draw (declared before the
  init early-return): 330 us/draw. Fixed -> 2 us/draw.
- gpu_backend.c: surfaces keyed by address only, sized from pitch; binds
  skipped when unchanged; readback asynchronous (one flip later).
- Toolkit nv2a_pb_exec.c (uncommitted, on fix/ohci-ram-named-buffers branch
  working tree): per-batch post-transform vertex cache (RECOMP_NO_VCACHE=1
  off), vertex programs on a worker pool (RECOMP_VSH_THREADS), profiler
  RECOMP_PB_PROFILE=1, diagnostic RECOMP_SKIP_TEX. Visuals checked same.
- Now: executor idle ~66%; the **game thread (~87% CPU) is the limit**,
  likely spin-waiting (D3D fence/vblank waits). Next: find where it spins
  (templates/runtime/recomp_types.h RECOMP_CALL_PROFILE, or the watchdog
  stack), then decide (e.g. flip pacing, yield in the wait).

### Locked 60 fps (2026-10-24)

Training level holds 60.0 flips/s while moving (18-42k draws per 5 s).
What it took after the 53-59 fps state, found with RECOMP_SAMPLE /
RECOMP_SAMPLE_ALL (main.c; tools/samples.py, tools/sample_thread.py read
sample_stacks.txt against build/Release/spiderman_recomp.map):
- Toolkit kernel_bridge.c: paced vblank at NTSC 59.94 Hz (60000/1001), not
  60; the game's frame limiter is 1/60 s of TSC time, and at exactly 60 Hz
  the two tied (RECOMP_VBLANK_HZ overrides). RECOMP_TIMER_STALLS=1 names any
  timer-thread pass over 20 ms.
- Toolkit xbox_memory_layout.c: RECOMP_NV2A_FAST_KICK=1 write-traps the PFB
  page and clears D3D's kickoff bit (0x100410 bit 16) at once; the game
  thread spent 27% spinning on it in sub_002F2960 (D3D KickOff).
- Seeds 0x002B8B90, 0x002B8C32: CRT _trandisp2 math handlers, failing (and
  logging) every frame.
- stderr through a 1 MB pipe drained by its own thread (main.c,
  RECOMP_LOG_DIRECT=1 to disable): file writes under the CRT's stderr lock
  held the timer thread (vblank clock) 40-140 ms at a time. The executor's
  "[GPU] draw #N" line now stops after 4000 draws; ICALL failures are
  rate-limited in recomp_manual.c.
- Game thread now ~85% in its own frame limiter (sub_000F6FF0): headroom.

## Wishlist (later, once it draws and takes input)

  DualSense doesn't speak natively. Works today through DS4Windows / DualSenseX
  (both on the user's Desktop) presenting it as an Xbox pad. Native support

- **Resolution: done (2026-10-25).** `RECOMP_RENDER_SIZE=<w>x<h>` (play.bat:
  1920x1080, the 4:3 picture stretched to 16:9) with RECOMP_GPU_RENDER and
  RECOMP_D3D_PRESENT. gpu_backend.c makes every target w/640 x h/480 its
  guest size; vertices stay in guest pixels (only the viewport grows). At
  flip each scaled target is shrunk on the GPU for the guest-memory readback
  (dumps, GDI, anything read back), and the shown one is read back at full
  size and handed to the window (toolkit d99e504,
  xbox_FramebufferWindowPresentHiRes). 58-60 fps in ORIGIN_A and Training.
  Needed the combiner shader without an indexed register array: as
  float4[16] it went to scratch memory and 1080p ran 9-20 fps. True
  widescreen (more field of view) would need the game's projection changed.

## Side study: Kraven levels into the PS2 version (2026-10-24)

PS2 disc: `Desktop\Spider-Man (USA) (v1.00).iso`, program `SLUS_203.36`.

- Kraven = mission 7, `M7bronxzoo\bronxzoo_b/_c`, files `levels\ZOO_B.xbs` /
  `ZOO_C.xbs`, Xbox-only. PS2 has the other 24 levels.
- **The PS2 program still contains Kraven's code**: AI states (`kraven_melee`,
  `kraven_rifle`, `KRAVEN_JUMP_A/B`) and script commands (`kraven_begin_berserk`,
  `kraven_break_rifle`, `kraven_360machette_*`). Only mission 7's two entries are
  missing from its level table (PS2 0x4423B0.., goes oscorp_e -> bridge_a).
- Level files share one container (magic `0x00055AFE`, 3 sections, both
  little-endian). Xbox payload is zlib at 0x40; PS2 is raw at 0x800. Contents
  are platform-specific: Xbox textures (`.tga` names) vs PS2 TIM2, and each
  console's mesh format.
- Memory: biggest PS2 level 10.3 MB loaded; ZOO_B is 11.3 MB on Xbox, and PS2
  levels run ~10-15% smaller than their Xbox versions, so it likely fits.
- The real work: an Xbox -> PS2 level converter (textures, meshes, the rest),

## Sound-effect glitches: FIXED (2026-10-27)

**Cause.** The toolkit's "SSL tick" raises APU ISTS bit 3 every 2048 samples
(added for Black, whose DirectSound needs it). Spider-Man's DirectSound reads
that bit as a fault: ISR 0x00341076 -> sub_00341026 -> sub_003408CE resets
the GP/EP, reloads them (sub_003404F6) and calls
KeStallExecutionProcessor(10000) -- a 10 ms busy-wait. The ISR runs on the
APU frame thread, so every tick stopped the sound for 10.3 ms: ~45% of the
audio lost (800 of 1500 frames/s, "trap held the VP 10.4 ms" x hundreds).
Found with RECOMP_APU_VLOG (ISR timing) + a hang_stacks.txt sample of the
frame thread (86% in xbox_KeStallExecutionProcessor under sub_003408CE).
The Oct 25 DPC-wake change was not the cause: the trap is cleared 0.1 ms in.

**Fix.** Toolkit: `RECOMP_ISR_NO_STALL=1` makes KeStallExecutionProcessor
return at once while a device ISR runs on its device's own thread
(xbox_StallInDeviceIsr, set around apu_call_isr). Now in play.bat and in
settings.c's required list (launcher). Result in the scripted test: no
trapped frames, no long ISRs, 0 underruns, full 1500 frames/s, pause menu
silent, gameplay audio normal.

**Tried and rejected:** `RECOMP_APU_SSL_TICK=0` (also added; =once fires it
once). No resets, but a loud 9-value buzz whenever the game is paused -- the
game relies on the reset. Leave it unset.

**Still open:** the game still resets the GP/EP every ~43 ms (cheap now).
If an effect is still cut short, that reset is the first suspect.

**Diagnostics added (toolkit, log only):** RECOMP_APU_VLOG now also prints
long ISRs and who cleared a trap; RECOMP_TIMER_LOG=1 logs every KeSetTimer;
the timer thread prints its tid. Toolkit diff (uncommitted, on
fix/nv2a-backend-stale-texture): backup_2026-10-27\toolkit_after_sound_fix.patch.
Git commit was not done from the session (it could not clean git's lock files).

**Test scripts:** sound_test_auto.bat (plays itself via sound_test_pad.txt,
quits at 210 s, logs sound_log.txt); test_nostall.bat / test_baseline.bat /
test_ssl_off.bat (record audio_*.wav); build_only.bat rebuilds.
